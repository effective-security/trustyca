# Code map

Navigation index: concept → owning file → entry points → invariants. Read the
matching concept row and package section, then the source and its tests.
Paths are repository-relative; a bare file name shares the directory of the
path before it, and files in a package section are in that package. Use
codebase-memory-mcp (`search_graph`, `trace_path`, `get_code_snippet`) for
symbols and callers, with `project="trustyca"` (see [MCP.md](../MCP.md));
check the index status and coverage before treating a miss as absence.

- [AGENTS.md](../AGENTS.md): contribution rules and validation commands.
- [README.md](../README.md): build targets, local setup and client config.
- [ROADMAP.md](../ROADMAP.md): planned work.
- `FINDINGS.md`: local list of known defects. It is gitignored in this
  public repository; committed files do not reference its IDs.
- [design/DESIGN.md](design/DESIGN.md): scope, tenancy and authorization,
  domain model, issuers, profiles, signing, revocation and APIs.
- [PLAN.md](PLAN.md): implementation phases of DESIGN.md; phase 1 (orgs,
  projects, members, authorization) is done, phase 2 has its DB layer and
  the CA library (`internal/ca`: issuer registry, keys, bootstrap), phase 3
  the CA service: issuers, profiles, roots, signing, certificates,
  revocation and the current CRL, and phase 4 CRL publishing (the
  publisher of `internal/ca`, `PublishCrls`, the `crl_renewal` task) and
  the `cert_status` task, phase 5 the CIS service (`server/service/cis`:
  the JSON and gRPC API for authenticated callers), phase 6 the operator
  tooling (`internal/ctl/admin`: the `ca` commands of `trustycactl` and the
  onboarding of an org, the support lists of `privpb.Admin`, the CIS
  commands of `trustyca`), phase 7 the hardening, phase 8 the AIA
  service (`server/service/aia`: the public AIA, CRL and OCSP routes of
  the issued certificates on a plain HTTP listener), and phase 9 the
  signing plane (`privpb.Backend` on the backend listener, the CA of the
  service identities with an explicit org; `pb.CA` on the wfe, the CA of
  the tenants with the org of the token, forwarding every call; named
  service clients), and phase 10 the Web UI sessions (the cookie session
  and `POST /v1/auth/org`, the `local` identity provider, token revocation,
  the container integration tests of `tests/integration`). Completed phases
  keep a one-line summary there; open work is listed after them.
- `Documentation/api/`, `Documentation/cli/`: generated by `make docs`; do
  not edit or use for source discovery.

## Module layout

```text
cmd/             trustyca (public CLI), trustycactl (admin CLI), trustycasvc (service)
api/             public CLI, clients, protobuf contracts and version
privpb/          private Admin protobuf contracts
internal/        authorization, CA core (issuer registry, keys, bootstrap) and its API conversions (pbconv), configuration, persistence, admin CTL, metrics
server/          application/container wiring, HTTP/gRPC services and tasks
sql/trustycadb/  migrations and local database bootstrap scripts
mocks/, tests/   generated mocks (gitignored), shared fixtures, container builders, the load tool (tests/load) and the container integration tests (tests/integration)
etc/             service configuration, CA bootstrap and development certificates
```

### api/cli

Public trustyca command, client connections and output formatting.

- cli.go: Cli, Context, IsJSON, Reader, AfterApply, RPCClient, HTTPClient, AuthClient, OrgsClient, CISClient (the public CIS, no token)

Invariant: Cli.AfterApply changes process-wide xlog and time formatting, so CLIs are never parsed concurrently in one process: the CLI test suites do not call t.Parallel. A missing config file is created from defaultConfig under `--storage`, `TRUSTYCA_STORAGE` or DefaultStoragePath. A client that authenticates (`RPCClient(false)`, HTTPClient(false)) sends `TRUSTYCA_AUTH_TOKEN` when the variable is not empty, else the token of the storage folder, and fails with `unable to load auth token` without either, for every server: a host of the config file only selects the storage folder and the trusted CA (TestRPCClient_StoredToken). StatusClient and CISClient dial without a token.

### api/cli/clisuite

CLI test suites with fixture-backed HTTP servers and gRPC mocks.

- suite_grpc.go: TestSuiteGrpc (MockAuth, MockStatus, MockOrgs, MockCIS), SetupSuite, SetupMockGRPC, SetupTest
- suite_http.go: TestSuite, CapturePrint, HasNoText, SetupSuite, TearDownSuite

Invariant: CapturePrint records output with the mock server address replaced by `{server}`; TearDownSuite compares it with the suite's golden file, testdata/prints\_<suite test>.txt (testutils.CheckGolden), and rewrites the file only with TRUSTYCA_UPDATE_GOLDEN=1. The gRPC suite listens on an ephemeral port and replaces format.NowFunc per test. Suites share CLI globals, so they are not parallel.

Invariants:

- Every lookup names its tenant scope: a label resolves in the project, then in the org, never in the platform or in another org; the platform scope (zero org) resolves only platform rows. An inactive profile is not found and does not fall back. Issuers of any status are found, `Resolve` needs Active, `IssuerBySKID` (OCSP, CRL) accepts Active and Archived. Failed resolutions are not cached.
- The built `authority.Issuer` is cached by row ID (unique across orgs), the resolutions by `(org, project, label)` of the request, both in `expirable` LRUs with the TTL and size of Options (`DefaultCacheTTL` 5 minutes, `DefaultCacheSize` 1000 issuers; the label caches hold four times the issuers). `InvalidateIssuer` drops the issuer and its label; `InvalidateProfile` with a zero project drops the label in every project of the org. A row newer than the built one (`updated_at`) rebuilds the issuer; an older row does not replace it. One issuer is built at a time under a lock striped by ID.
- A profile is registered on the issuer under `{profile ID}@{updated_at ms}`, the name the service passes in `csr.SignRequest.Profile`; the issuer keeps old versions until it is rebuilt. The delegated OCSP profile of an issuer is resolved in the issuer's scope at build time and registered under its label, and must bind to the issuer; a missing or unbound one fails the build with a plain error, never `ErrProfileNotFound`, since the profile of the request exists and the service reports a build failure as Internal.
- `authority.Issuer.Sign` and `SignOCSP` are shared across requests; `createIssuer` builds a self-signed certificate without chain or roots, as xpki does for roots, because the bundler refuses a self-signed leaf under trust roots.
- Keys: a provider key is referenced by its `pkcs11:` key URI in `key_id` (manufacturer in `key_provider`) and loaded with `cryptoprov.Crypto.NewSignerFromPEM`; a software key is wrapped by the data protection provider into `key_protected` (base64url of `Protect`), with `key_provider = inmem` and the key label in `key_id`. `KeyRefFromExport` tells them apart by the `pkcs11:` prefix, since AWS KMS exports its URI as bytes too. Software keys are allowed by default and refused with `ErrSoftwareKeysDisabled` after `DisableSoftwareKeys` (every key that would be stored wrapped: the export of the inmem provider, the PEM of an import, a bootstrap key file; the wrapped keys of existing rows still load), which the container applies unless `ca.allow_software_keys` is set, and a prod environment refuses the setting at the start (provideCA). `Provider(name)` matches `manufacturer` or `manufacturer/model`, the default first. A Pending issuer's `skid` is `SubjectKeyID` of its key. `Destroy` needs a `cryptoprov.KeyManager`; software keys are destroyed by the row.
- Rows: `chain_pem` holds the CA certificates between the issuer and the root (`parent.Issuer.PEM()` for a signed issuer, `bundle.CACertsPEM` for an import or activation), `root_pem` the root, and a self-signed issuer is its own root; stored PEM comes from `certutil.EncodeToPEMString` and has no trailing newline. `NewSignedIssuer` needs a CA profile (`CAConstraint.IsCA`) resolved in the parent's scope and refuses `Type = Root` before it generates a key: a Root is self-signed, and only a self-signed certificate becomes a trust anchor (`NewRootIssuer`, `ImportIssuer`). It also checks the path length before the key (`checkPathLength`): every ancestor of the parent with a pathLenConstraint, walked by issuer through the parent's bundle, must allow one more CA, and the profile's `max_path_len` must not exceed what the chain leaves (RFC 5280 section 4.2.1.9); xpki's own check is commented out. The error strings carry the `disallows` and `exceeds` markers, so the service answers InvalidArgument.
- `Registry.Bootstrap` is idempotent, and safe when several instances start against one fresh DB at once (the service instances, the test packages of `make test`): an issuer insert that loses the race to another instance (`db.IsUniqueViolation` of the label or key) continues with the row that instance registered, after the same key check as a lookup that finds it; self-signed certificates of the root bundle become private platform anchors; a registered issuer with the same SKID has its settings refreshed when they differ (`UpdateIssuer` with the config, never `crl_number`); a certificate for another key is an error; the parent of a file issuer is set when its IKID is a registered platform issuer; profiles are upserted by label, with `*` for a profile without an issuer label; every profile is validated. A `disabled` entry archives its registered Active issuer (`BootstrapResult.Archived`), so that it stops signing on every instance; an entry enabled again makes its Archived issuer Active in the same update as the settings; a Destroyed or Pending one is an error. The anchor of a registered root issuer is registered again on every start from its stored certificate (`RegisterRoot` is an upsert), so an anchor an earlier start failed to write is repaired. After the profiles, every enabled issuer is built through the cache: a key that does not unprotect or a delegated OCSP profile that does not bind fails the start, not the first request. File URL templates must use `:ISSUER_ID`, the loader expands `${...}`.
- Rows shared between goroutines are never formatted with `xdb.ID.String` or `UnderscoreString`, which cache without synchronization: the package uses `idString` (`xdb.IDString(id.UInt64())`), and `AuthorityProfile` converts a cached profile row through `model.CertificateProfile.Definition`, never `Pb`. `NewSignedIssuer` copies the parent's ID by value into the new row.
- CRLs (crl.go, DESIGN.md section 8): `CrlPublisher` takes the write-capable `db.CaDb` next to the registry and is shared by the service and the `crl_renewal` task. `PublishCrl` takes an Active or Archived row read from the DB (its `crl_number` is the current one; another status is `ErrIssuerNotActive`, an expired certificate `ErrIssuerExpired`), reads the current CRL (`db.GetCrl`) and signs when it is due (`CrlDue`: no current CRL, or `next_update` not after now plus the `CrlRenewal` of the row settings, read by `crlRenewal` as the registry configures the issuer) or forced; otherwise it returns the current CRL with false. The issuer and its key are loaded through the registry only when a CRL is signed. The entries are the revocations of the IKID across every org whose certificate is valid now (`ListRevoked` with `AllOrgs`, `IKID`, `ValidAfter`, paged by cursor), with their reason codes; `ThisUpdate` is now truncated to the second, `NextUpdate` now plus `CrlExpiry`, capped at the issuer certificate's `NotAfter`; the number is `crl_number + 1`, stored by `db.PublishCrl` with the number in one transaction. On `db.ErrStaleCrlNumber` the row and the current CRL are read again and the CRL signed once more (`publishAttempts`), unless the other publisher's CRL is not due and the publish is not forced. The PEM comes from `pem.EncodeToMemory` (trailing newline). `PublishCrls` lists the Active, then the Archived issuers of the scope (`ListIssuers` by status, `issuerPageSize` per cursor page), reads the current CRLs of each page in one query (`db.GetCrls`, never a lookup per issuer) and counts the skipped (not due, or expired certificate) and failed issuers; a failure is logged at ERROR with the issuer and never stops the run; only a failure to list the issuers or to read their CRLs is returned, with the CRLs published before it in the result. Metrics: `CACrlPublished` and `CAFailPublishCrl` by issuer label.
- Tests (`ca_test`) use a map-backed fake `db.CaDb` (fake_test.go: issuers, profiles, roots, revocations and CRLs, with `Stale` to make the next publishes lose to another publisher and `Race` to make the next issuer insert lose to another instance), the `inmem` provider and a symmetric data protection provider (fixture_test.go), and create every issuer through the package; crl_test.go verifies the signed CRLs with `x509.ParseRevocationList`; bench_test.go measures the warm and cold resolution against a single `authority.Authority` (PLAN.md phase 2a).

Tenancy fails closed in the DB layer: a List names its org scope (OrgID, Platform or AllOrgs) or fails with ErrOrgScopeRequired, and every mutation of an existing row (Update, Activate, Revoke, Delete, the FOR UPDATE read of RevokeCertificate) matches the exact org scope with `org_id IS NOT DISTINCT FROM` the org, so another org's row is not found or not deleted; a Get by ID returns the row of any scope and the caller verifies its org and project. Lifecycle transitions of an issuer are not enforced by the DB layer. The CA sentinel errors are re-exported from pgsql and query, so services compare them with errors.Is without importing those packages; IsUniqueViolation (pgsql/errors.go) tells a unique violation of a named constraint prefix by the driver's SQLSTATE and constraint name, or by the driver's message for the fakes of the tests, so a service maps a conflict (AlreadyExists) and the bootstrap a lost insert race without parsing messages.

The Authority Information Access service (DESIGN.md section 9.4): the binary routes the issued certificates point at, served over the plain HTTP `aia` listener to any caller, REST only (no gRPC API): the issuer certificate (AIA caIssuers), the current CRL (CDP) and the OCSP responder, which forwards to the backend service (privpb.Backend.SignOCSP).

Invariants:

- The service reads `db.CaReadonlyDb` (`GetIssuerBySKID`, `GetCrl`) and holds no issuer keys; every lookup is by the key identifier in the path or by the OCSP request itself, and nothing is listed. There is no authentication: the `aia` listener has no identity map, every caller is a guest, and its `authz.allow_any` lists the AIA and status routes only, so a path without a rule is refused (server/app Test_Authz_CAMethods). A Pending issuer, which has no certificate, is not found (`issuedIssuer`).
- `New(cfg, caDb, backend)` takes the shared.BackendLocator of the backend the OCSP requests are forwarded to; without one every OCSP request answers tryLater. The Factory builds it over the server's discovery and the container's client factory: the backend service of the same process when it runs one, else a client of `config.BackendServerName` with the `aia` service client (the `trustyca-aia` identity, allowed `Backend.SignOCSP` only), created on the first OCSP request, never at startup, because porto's gRPC client blocks until the backend is reachable and the listeners start in any order; a failure answers tryLater and the next request tries again; the client is kept and closed with the service. The forwarded call is bounded by `caCallTimeout`.
- OCSP (`ocspResponse`, RFC 6960): the request of a GET is the URL-encoded base64 in the path of `/v1/ocsp/*body` and `/v1/ocspi/:ikid/*body` (the issuer segment is not used: the request carries the issuer, ROADMAP RM-003), the request of a POST is the body, bounded by `maxOCSPRequestSize` whatever the request declares. A request that does not parse is malformedRequest with 400 before anything is forwarded. The signed responses are cached by the SHA-256 of the DER request (`ocspCache`, an LRU of `aia.ocsp_cache_size`, default 10000) until the `NextUpdate` the CA signed, which the cache checks on every hit, so a request with a nonce is never answered from another's entry, and a revocation reaches the AIA when the cached `good` answer expires (`ocsp_expiry` of the issuer) or the entry is evicted; a response already past its `NextUpdate`, or one that does not parse, is passed through with `no-store` and not cached. A failure of the CA is an OCSP error response with the HTTP status of the porto error: 400 malformedRequest, 404 unauthorized (an issuer the CA does not serve), 503 tryLater (unavailable, a timeout, throttling, or no client), else 500 internalError; errors are never cached. Metrics: `AIACacheHit`/`AIACacheMiss` with type `ocsp`, `AIADownloadSuccessOCSP`/`AIADownloadFailOCSP`.
- The binary routes serve DER (`derOf`, the first PEM block): the issuer certificate of `/v1/cert/:ikid` (`application/pkix-cert`, cached for `certMaxAge`, a day, since a key identifier never changes certificate) and the current CRL of `/v1/crl/:ikid` (`application/pkix-crl`). `writeCacheable` sets `Cache-Control: public, no-transform, must-revalidate, max-age=` until the expiry (`NextUpdate` of a CRL or OCSP response), `Last-Modified` (`ThisUpdate`, or the start of the certificate's validity), `Expires` and an `ETag` (the quoted SHA-256 of the body, answered with 304 to `If-None-Match`); a body already expired is served with `no-store`. A missing row is a JSON not-found error (`marshal.WriteJSON`) and counts in `AIADownloadFail*`.

It has no IdP: AuthorizeHandler redirects to the callback on the public host of the authorize request (`?code=local`), never to the configured auth_url, so the cookies of a cookie session are set for that host. AuthProviderForEmail maps an address with `local+` to it, with no invitation; elsewhere `local+` is part of an ordinary address. The flow signs in the address without the prefix (localUserInfo: the email is the login's external ID, the name its local part), or localUser without one.
- Cookie session (`response_type=cookie`): the callback sets the auth cookie (the token, HttpOnly) and the CSRF cookie (32 random characters, readable by a script), both Secure, SameSite=None, Path=/, on `identity_map.cookies.domain`, until the token expires with `remember_me`, else for the browser session, and lands on the redirect URI with `cookie_set=true&csrf=<CSRF cookie name>&expires_in`, never the token. porto maps the cookie to the identity (MethodJWTCookie) only with the CSRF double submit: the `X-CSRF-Token` header (`x-csrf-token` metadata) equal to the CSRF cookie on every gRPC and gRPC-Web call and on unsafe REST methods; otherwise the caller is a guest, never an error. GetUserToken, SelectOrg and AuthOrgHandler omit AccessToken for a cookie session (omitCookieAccessToken).
- SelectOrg (gRPC, `POST /pb.Auth/SelectOrg`) returns a new token with the original expiry and cannot set a cookie; AuthOrgHandler (`POST /v1/auth/org`, pb.PathForAuthOrg) runs the same selectOrgToken and, for a cookie session without an Authorization header, writes the token into the auth cookie with a new CSRF cookie (persistent with RememberMe), so the console re-reads the CSRF cookie after it. A caller with Authorization gets the token and keeps its cookies.
- RevokeToken refuses a caller without a token (Unauthenticated `no token to revoke`), answers Unimplemented without a revocation, and records UserSignedOut, or TokenRevoked for an API key token. RevokeTokenHandler (DELETE `/pb.Auth/RevokeToken` only: a GET would sign a cookie session out without the CSRF check) removes both cookies first, whatever the outcome, and writes the sanitized error of revoke. RemoveCookieHandler (`DELETE /v1/auth/removecookie`, skip_auth) removes them without revoking.
- AuthDoneHandler (`/v1/auth/done`, GET and POST, skip_auth) renders the token it is given as plain text.
- Events (internal/events, source `auth`): the callback records UserSignup for a new user's first login (LoginUser returns the login and user with one ID), OrgMemberAccepted / ProjectMemberAccepted for each accepted invite, OrgCreated and ProjectCreated for the default org and project (initialOrg), and UserSignedIn once the token is issued; selectOrgToken records UserSignedIn in the org; RevokeToken records UserSignedOut, or TokenRevoked for an API key token; AuthenticateAPIKey records APIKeyLogin after it signs the token.

  `make drop-sql start-sql` **only for a disposable local database**. The

  LocalStack and KMS; tests load `etc/dev/trustyca-config.unittest.yaml`.
  `make test` starts nothing.
- `make test` runs the tests; `make testshort` passes `--test.short`, but
  package setup can still need the local stack. `make test RACE=true` enables
  the race detector.
- `make lint` runs formatting and golangci-lint (`.golangci.yml`, which
  excludes SA1019); `CI=true` skips staticcheck/unused. `make vulns` runs
  govulncheck (install it first).
- `make covtest` writes per-package coverage and `coverage.out`;
  `make coverage` opens the HTML report (`.project/gomod-project.mk`).
- `.github/workflows/build.yml` prepares generators, builds binaries and
  starts fixtures. Pushes run `make test`; PRs run `make covtest` and publish
  a coverage status against `MIN_TESTCOV`, which the workflow does not set
  yet; both run `make docker-citest`. Lint and race checks are local.
- `make docker-citest` builds the images (`make docker-build docker
  docker-tester`: the binaries link the PKCS#11 provider with cgo, so
  docker-build compiles them in `golang:<go.mod version>-trixie` from the
  host module cache, read-only and offline, and the `Dockerfile` runs them
  on Debian trixie: `distroless/base-debian13` for the service,
  `debian:trixie-slim` for the test runner) and runs tests/integration in a
  compose stack of its own, with its own PKI and database.
- `make docs` regenerates `Documentation/api/` and `Documentation/cli/`;
  build the CLI binaries first.
- `go run ./tests/load -rows N -load -explain -sign 2000` fills a disposable
  database (`trustycadb_load`, created with the superuser of the dev
  container) with synthetic certificates and prints the plans and timings of
  the CA queries; `-drop` removes it. Documentation/perf/load-certificates.md
  keeps the last 10M-row run.
- A `.VERSION` change pushed to main creates a `<.VERSION>.<commit count>`
  tag through `build.yml`.
