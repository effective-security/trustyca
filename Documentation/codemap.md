# Code map

Navigation index: concept → owning file → entry points → invariants. Read the
matching concept row and package section, then the source and its tests.
Paths are repository-relative; a bare file name shares the directory of the
path before it, and files in a package section are in that package. Use
codebase-memory-mcp (`search_graph`, `trace_path`, `get_code_snippet`) for
symbols and callers, with `project="trustyca"` (see [MCP.md](../MCP.md));
check the index status and coverage before treating a miss as absence.

- [AGENTS.md](../AGENTS.md): contribution rules and validation commands.
- [README.md](../README.md): build targets, local setup and client config.
- [ROADMAP.md](../ROADMAP.md): planned work.
- `FINDINGS.md`: local list of known defects. It is gitignored in this
  public repository; committed files do not reference its IDs.
- [design/DESIGN.md](design/DESIGN.md): scope, tenancy and authorization,
  domain model, issuers, profiles, signing, revocation and APIs.
- [PLAN.md](PLAN.md): implementation phases of DESIGN.md; phase 1 (orgs,
  projects, members, authorization) is done, the CA phases are not.
- `Documentation/api/`, `Documentation/cli/`: generated by `make docs`; do
  not edit or use for source discovery.

## Module layout

```text
cmd/             trustyca (public CLI), trustycactl (admin CLI), trustycasvc (service)
api/             public CLI, clients, protobuf contracts and version
privpb/          private Admin protobuf contracts
internal/        authorization, configuration, persistence, admin CTL, metrics
server/          application/container wiring, HTTP/gRPC services and tasks
sql/trustycadb/  migrations and local database bootstrap scripts
mocks/, tests/   generated mocks (gitignored), shared fixtures and container builders
etc/             service configuration, CA bootstrap and development certificates
```

## Packages

Tests live beside the source (`<file>_test.go`, fixtures in `testdata/`);
read them before expanding scope. Test notes below list only what is not
discoverable from file names. Most packages have no `doc.go` yet: the ones
that do are api/cli, api/cli/clisuite, internal/ctl/ctlsuite,
internal/db/schema and tests/testutils. Add one when you change a package.

### api/cli

Public trustyca command, client connections and output formatting.

- cli.go: Cli, Context, IsJSON, Reader, AfterApply, RPCClient, HTTPClient, AuthClient, OrgsClient

Invariant: Cli.AfterApply changes process-wide xlog and time formatting, so CLIs are never parsed concurrently in one process: the CLI test suites do not call t.Parallel. A missing config file is created from defaultConfig under `--storage`, `TRUSTYCA_STORAGE` or DefaultStoragePath.

### api/cli/clisuite

CLI test suites with fixture-backed HTTP servers and gRPC mocks.

- suite_grpc.go: TestSuiteGrpc, SetupSuite, SetupMockGRPC, SetupTest
- suite_http.go: TestSuite, CapturePrint, HasNoText, SetupSuite, TearDownSuite

Invariant: CapturePrint records output with the mock server address replaced by `{server}`; TearDownSuite compares it with the suite's golden file, testdata/prints_<suite test>.txt (testutils.CheckGolden), and rewrites the file only with TRUSTYCA_UPDATE_GOLDEN=1. The gRPC suite listens on an ephemeral port and replaces format.NowFunc per test. Suites share CLI globals, so they are not parallel.

### api/cli/command

Public trustyca commands: auth, org, project, member, API key and status.

- apikey.go: APIKeyCmd, APIKeyCreateCmd, APIKeyListCmd, APIKeyDeleteCmd

Tests: suite_test.go runs TestSuite (HTTP fixtures from api/cli/testdata) and TestRpc (gRPC mocks); their golden files are testdata/prints_TestSuite.txt and testdata/prints_TestRpc.txt. auth_internal_test.go drives the login listener directly.

### internal/authctx

Tenant context, grants, roles, scopes and API authorization.

- allowed.go: GetAllowedMethods, GetCallerScope, ProjectFromRequest
- authorizer.go: GrantsProvider, Authorizer, NewAuthorizer, ErrInsufficientRole, ErrAccessDenied, ErrOrgNotSelected
- authz.go: OrgRequester, ProjectRequester, ServiceRolePrefix, NewAuthUnaryInterceptor, CheckAccess
- ctx.go: TrustyCtx, Claim*, Handler, FromContext, FromRequest, NewTrustyCtx, NewAuthUnaryBackendInterceptor
- grants.go: Grants, GrantsFromMemberships, ResolvedOrgRole, Roles, HighestRole, CanGrantOrgRole, CanGrantProjectRole
- roles.go: CanAssumeRoles, ParseRole, CanAssumeRole, AllowsRole, OrgRoles, ProjectRoles
- scopes.go: Scope* constants, DefaultAPIKeyScopes, ParseScopes, HasScope, HasScopes, IsKnownScope

Invariants:

- The org comes from the token, never from the request: an explicit OrgID that differs from the token is refused, except from a `trustyca-*` service role, which passes tenant scope explicitly.
- Permissions are resolved from DB grants at request time; the org role claim is informational. Grants and projects are cached for 3 minutes; membership and project mutations call InvalidateUser / InvalidateProject. provideAuthorizer gives the app one Authorizer, so a service's invalidation clears the interceptor's cache.
- An inactive project, a project of another org and an unknown project are all ErrAccessDenied, so project existence does not leak across orgs.
- privpb.Admin accepts `trustyca-*` service roles only (`trustyca-viewer`: Get, List and SupportTenant); pb.Status accepts any caller, and pb.Auth is gated by the server authz config only. API keys are checked against their scopes, never memberships, and only on methods whose allowed roles include APIKey.

Tests: an xdb.ID caches its string form without synchronization, so parallel tests build their own IDs (the fixture constructors in authctx_test.go, specRows in roles_test.go) rather than share one.

### server/service/auth

OAuth login, code exchange, org selection, API key authentication and token revocation.

- apikey.go: AuthenticateAPIKeyHandler, AuthenticateAPIKey, validateHMAC, findAPIKey
- auth_service.go: Service, Factory, RegisterRoute, Protect, Unprotect, SetAuthProvider, AuthProviderForEmail
- authorize.go: AuthorizeHandler, Request, State, OTCState
- callback.go: GetProviders, AuthProvidersHandler, AuthDoneHandler, CallbackHandler, GetUserInfo, ExchangeCode
- cookies.go: RemoveCookieHandler, setAuthCookie, resetAuthCookie
- tenant.go: SelectOrg, initialOrg, selectOrg, setOrgClaims
- userinfo.go: UserinfoHandler, GetUserToken, Caller, RevokeToken, RevokeTokenHandler, GetAllowedMethods, GetCallerScope

Invariants:

- OAuth state is protected with dataprotection (Protect/Unprotect); DPoP-bound logins get the DPoP audience. The callback answers in the requested response mode: query, fragment or form_post.
- A login selects the first accessible org, or creates the configured default org and project for a user without grants (initialOrg). Tokens carry the selected org, the resolved role for display and scopes; permissions come from authctx at request time.
- SelectOrg returns a new token with the original expiry; it does not set a cookie. RevokeTokenHandler (GET and DELETE) clears the auth cookie before revoking.
- Auth cookies are HttpOnly, Secure and SameSite=None, with a readable CSRF companion cookie; names and domain come from the server's identity_map.cookies.
- AuthDoneHandler (`/v1/auth/done`, GET and POST, skip_auth) renders the token it is given as plain text.

Tests: auth_service_test.go TestMain starts one auth service over the configured database and Redis. A test that changes its BaseURL or registers a provider with SetAuthProvider is not parallel.

### server/service/orgs

pb.Orgs: orgs, projects, members, invites and API keys of the org selected in the token.

- apikey.go: CreateAPIKey, ListAPIKeys, DeleteAPIKey
- members.go: GetUserOrgs, GetUserMemberships, GetMembers, AddMember, ChangeMemberRole, DeleteMember, DeleteInvite, checkLastOwner

- orgs_service.go: Service, Factory, OrgsHTTPHandler, RegisterRoute

Invariants:

- Tenant operations take the org from the token (tokenOrg) and validate project scope with the Authorizer; a project of another org is not_found.
- Grants follow authctx.Grants.CanGrantOrgRole / CanGrantProjectRole; an org always keeps an org-wide Owner (checkLastOwner). Every membership mutation invalidates the user's cached grants.
- A refusal the org's state causes (deleted org, last Owner) is preconditionFailed: HTTP 409 `conflict` with the message, gRPC FailedPrecondition. Do not use NewGrpcFromCtx with FailedPrecondition: the pinned porto maps it to HTTP 500 and hides the message. Return the error unwrapped: httperror.Wrap with a message rebuilds it from its code. A Go client of the gRPC API (proxypb, httperror.NewFromPb) still sees a 500.
- DeleteProject deactivates the project; memberships and invites are kept.

Tests: service tests use the fakeAuthorizer and fixtures in authorizer_test.go with mocktrustycadb; precondition_test.go checks the 409/FailedPrecondition contract over REST and gRPC.

## Build, test and CI

- Go 1.27 (`go.mod`). `make tools` installs the lint, coverage, docs, PKI,
  schema, migrate and mock tools listed in `Makefile`.
- `mocks/` and `api/version/current.go` are gitignored: run `make generate
  version` on a fresh checkout before building or testing.
- `make build` builds `trustyca`, `trustycactl`, `trustycasvc`. `make generate`
  runs `go generate ./...` (gomock); `make proto` generates public and private
  protobuf artifacts in Docker; run `make proto generate` when mocks or
  service interfaces depend on the change.
- Local fixtures: `make folders gen_test_certs start-localstack`, then
  `make drop-sql start-sql` **only for a disposable local database**. The
  compose stack (`docker-compose.trustyca.yml`) supplies PostgreSQL, Redis,
  LocalStack and KMS; tests load `etc/dev/trustyca-config.unittest.yaml`.
  `make test` starts nothing.
- `make test` runs the tests; `make testshort` passes `--test.short`, but
  package setup can still need the local stack. `make test RACE=true` enables
  the race detector.
- `make lint` runs formatting and golangci-lint (`.golangci.yml`, which
  excludes SA1019); `CI=true` skips staticcheck/unused. `make vulns` runs
  govulncheck (install it first).
- `make covtest` writes per-package coverage and `coverage.out`;
  `make coverage` opens the HTML report (`.project/gomod-project.mk`).
- `.github/workflows/build.yml` prepares generators, builds binaries and
  starts fixtures. Pushes run `make test`; PRs run `make covtest` and publish
  a coverage status against `MIN_TESTCOV`, which the workflow does not set
  yet. Lint, race checks and the container integration test are local;
  `make docker-citest` points to a `scripts/integration` folder that does not
  exist.
- `make docs` regenerates `Documentation/api/` and `Documentation/cli/`;
  build the CLI binaries first.
- A `.VERSION` change pushed to main creates a `<.VERSION>.<commit count>`
  tag through `build.yml`.
