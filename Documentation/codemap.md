# Code map

Navigation index: concept → owning file → entry points → invariants. Read the
matching concept row and package section, then the source and its tests.
Paths are repository-relative; a bare file name shares the directory of the
path before it, and files in a package section are in that package. Use
codebase-memory-mcp (`search_graph`, `trace_path`, `get_code_snippet`) for
symbols and callers, with `project="trustyca"` (see [MCP.md](../MCP.md));
check the index status and coverage before treating a miss as absence.

- [AGENTS.md](../AGENTS.md): contribution rules and validation commands.
- [README.md](../README.md): build targets, local setup and client config.
- [ROADMAP.md](../ROADMAP.md): planned work.
- `FINDINGS.md`: local list of known defects. It is gitignored in this
  public repository; committed files do not reference its IDs.
- [design/DESIGN.md](design/DESIGN.md): scope, tenancy and authorization,
  domain model, issuers, profiles, signing, revocation and APIs.
- [PLAN.md](PLAN.md): implementation phases of DESIGN.md; phase 1 (orgs,
  projects, members, authorization) is done and phase 2 has its DB layer;
  the CA library and the CA and CIS services are not.
- `Documentation/api/`, `Documentation/cli/`: generated by `make docs`; do
  not edit or use for source discovery.

## Module layout

```text
cmd/             trustyca (public CLI), trustycactl (admin CLI), trustycasvc (service)
api/             public CLI, clients, protobuf contracts and version
privpb/          private Admin protobuf contracts
internal/        authorization, configuration, persistence, admin CTL, metrics
server/          application/container wiring, HTTP/gRPC services and tasks
sql/trustycadb/  migrations and local database bootstrap scripts
mocks/, tests/   generated mocks (gitignored), shared fixtures and container builders
etc/             service configuration, CA bootstrap and development certificates
```

## Packages

Tests live beside the source (`<file>_test.go`, fixtures in `testdata/`);
read them before expanding scope. Test notes below list only what is not
discoverable from file names. Most packages have no `doc.go` yet: the ones
that do are api/cli, api/cli/clisuite, internal/ctl/ctlsuite,
internal/db/schema, internal/events and tests/testutils. Add one when you
change a package.

### api/cli

Public trustyca command, client connections and output formatting.

- cli.go: Cli, Context, IsJSON, Reader, AfterApply, RPCClient, HTTPClient, AuthClient, OrgsClient

Invariant: Cli.AfterApply changes process-wide xlog and time formatting, so CLIs are never parsed concurrently in one process: the CLI test suites do not call t.Parallel. A missing config file is created from defaultConfig under `--storage`, `TRUSTYCA_STORAGE` or DefaultStoragePath.

### api/cli/clisuite

CLI test suites with fixture-backed HTTP servers and gRPC mocks.

- suite_grpc.go: TestSuiteGrpc, SetupSuite, SetupMockGRPC, SetupTest
- suite_http.go: TestSuite, CapturePrint, HasNoText, SetupSuite, TearDownSuite

Invariant: CapturePrint records output with the mock server address replaced by `{server}`; TearDownSuite compares it with the suite's golden file, testdata/prints\_<suite test>.txt (testutils.CheckGolden), and rewrites the file only with TRUSTYCA_UPDATE_GOLDEN=1. The gRPC suite listens on an ephemeral port and replaces format.NowFunc per test. Suites share CLI globals, so they are not parallel.

### api/cli/command

Public trustyca commands: auth, org, project, member, API key and status.

- apikey.go: APIKeyCmd, APIKeyCreateCmd, APIKeyListCmd, APIKeyDeleteCmd

With `--no-browser` there is no listener: the flow ends on the server's `/authenticated` page with the token in the URL fragment (`response_mode=fragment`), never in a query string.

Tests: suite_test.go runs TestSuite (HTTP fixtures from api/cli/testdata) and TestRpc (gRPC mocks); their golden files are testdata/prints_TestSuite.txt and testdata/prints_TestRpc.txt. auth_internal_test.go drives the login listener directly.

### internal/authctx

Tenant context, grants, roles, scopes and API authorization.

- allowed.go: GetAllowedMethods, GetCallerScope, ProjectFromRequest
- authorizer.go: GrantsProvider, Authorizer, NewAuthorizer, ErrInsufficientRole, ErrAccessDenied, ErrOrgNotSelected
- authz.go: OrgRequester, ProjectRequester, ServiceRolePrefix, NewAuthUnaryInterceptor, CheckAccess
- ctx.go: TrustyCtx, Claim\*, Handler, FromContext, FromRequest, NewTrustyCtx, NewAuthUnaryBackendInterceptor
- grants.go: Grants, GrantsFromMemberships, ResolvedOrgRole, Roles, HighestRole, CanGrantOrgRole, CanGrantProjectRole
- roles.go: CanAssumeRoles, ParseRole, CanAssumeRole, AllowsRole, OrgRoles, ProjectRoles
- scopes.go: Scope\* constants, DefaultAPIKeyScopes, ParseScopes, HasScope, HasScopes, IsKnownScope

Invariants:

- The org comes from the token, never from the request: an explicit OrgID that differs from the token is refused, except from a `trustyca-*` service role, which passes tenant scope explicitly.
- Permissions are resolved from DB grants at request time; the org role claim is informational. Grants and projects are cached for 3 minutes; membership and project mutations call InvalidateUser / InvalidateProject. provideAuthorizer gives the app one Authorizer, so a service's invalidation clears the interceptor's cache.
- An inactive project, a project of another org and an unknown project are all ErrAccessDenied, so project existence does not leak across orgs.
- privpb.Admin accepts `trustyca-*` service roles only (`trustyca-viewer`: Get, List and SupportTenant); pb.Status accepts any caller, and pb.Auth is gated by the server authz config only. API keys are checked against their scopes, never memberships, and only on methods whose allowed roles include APIKey.

Tests: an xdb.ID caches its string form without synchronization, so parallel tests build their own IDs (the fixture constructors in authctx_test.go, specRows in roles_test.go) rather than share one.

### internal/db

Database interfaces and the PostgreSQL provider constructor.

- doc.go: package overview and a construction example
- trustycadb.go: OrgsReadonlyDb, OrgsDb, CaReadonlyDb, CaDb, Provider, New, ErrAlreadyRevoked, ErrStaleCrlNumber, ErrRootConflict, ErrOrgScopeRequired

Invariant: OrgsReadonlyDb owns reads, OrgsDb mutations. New runs the migrations of `sql.migrations_dir`. go:generate owns mocks/mocktrustycadb. CaReadonlyDb owns the CA reads and CaDb the mutations (issuers, roots, profiles, certificates, revocations, CRLs); Provider implements both. CA rows with a zero OrgID are the platform's (`org_id IS NULL`). Tenancy fails closed in the DB layer: a List names its org scope (OrgID, Platform or AllOrgs) or fails with ErrOrgScopeRequired, and every mutation of an existing row (Update, Activate, Revoke, Delete, the FOR UPDATE read of RevokeCertificate) matches the exact org scope with `org_id IS NOT DISTINCT FROM` the org, so another org's row is not found or not deleted; a Get by ID returns the row of any scope and the caller verifies its org and project. Lifecycle transitions of an issuer are not enforced by the DB layer. The CA sentinel errors are re-exported from pgsql and query, so services compare them with errors.Is without importing those packages.

### internal/db/model

Database rows and their conversion to public API messages.

- apikey.go: Validate, IsExpired, Pb, NextPage
- certificate.go: NewCertificate, Validate, IsExpired, Pb, NextPage
- crl.go: Validate, Pb, NextPage
- doc.go: package overview
- event.go: Validate, Pb, NextPage
- invite.go: Validate
- issuer.go: Validate, SetCertificate, SetConfig, GetConfig, Pb, NextPage
- json.go: JSON, MarshalJSONValue, JSON.Unmarshal
- member.go: ScopeOf, Validate, Scope, Pb, FindMemberByUserID, FilterByOrg, OrgIDs, CountOrgRole, Invite.IsExpired
- org.go: Validate, Pb, NextPage
- profile.go: AnyIssuerLabel, NewCertificateProfile, Validate, SetConfig, Pb, NextPage
- project.go: ProjectAliasPrefix, Validate, Pb, NextPage
- records.go: RecordsResult, Pb
- revoked.go: Validate, NewRevokedCertificate, RevokedCertificate.Certificate, Pb, NextPage
- root.go: NewRootCertificate, Validate, Pb, NextPage
- tenancy.go: MaxLenForLabel, MaxLenForName, MaxLenForSha256, validateTenancy, validateLength
- user.go: User.Pb, Login.Pb, Validate, NewUser, FindLoginByID

Invariant: model.gen.go is schema-generated; handwritten files own validation and conversion. A membership or invite is org-wide when ProjectID is zero, project-scoped otherwise (ScopeOf). A CA row with a zero OrgID is the platform's and a project needs an org (validateTenancy). model.JSON is the raw value of the jsonb config columns of issuer and certificate_profile (typesmap.yaml): it writes an empty value as `{}` because the columns are NOT NULL, and PostgreSQL normalizes the stored document, so compare configs parsed (GetConfig, Pb), not as text. CertificateProfile.SetConfig strips the identity columns (ID, scope, labels, status, timestamps) from the stored definition and Pb restores them from the row; Issuer.Pb and CertificateProfile.Pb return an error because they parse the config. RevokedCertificate is the vw_revoked_certificate row, whose id is the revocation and certificate_id the certificate; NewRevokedCertificate composes it from the two rows. Tests compare xdb.ID values with UInt64(): the ID caches its string form, so assert.Equal on two IDs depends on which was printed.

Invariant: TryCreateEvent writes on its own goroutine with a background context and only logs failures. The metadata jsonb columns of event and certificate are NOT NULL and xdb.Metadata writes an empty map as NULL, so CreateEvent and RegisterCertificate pass query.MetadataArg, which writes `{}`, and query.LocationsArg does the same for the NOT NULL varchar[] locations columns. A method that writes more than one row opens a transaction with BeginTx and must run every statement on the returned provider (AcceptInvite); RegisterOrg runs its org insert on the outer provider, outside the transaction of the owner membership, and AcceptInvites adds each grant and deletes its invite without a transaction, returning the grants it created. LoginUser inserts a new login and user under one ID, so only a new user's first login returns both with the same ID. RegisterCertificate with an event inserts the certificate and the event (referencing the certificate) in one transaction. GetRevoked takes a GetRevokedRequest: the certificate ID, or the IKID and serial number as OCSP asks (migration 3 adds the unique index on them); both must match when both are given. RevokeCertificate locks the certificate (FOR UPDATE), inserts the revocation copied from the certificate row and sets the status in one transaction; a Revoked certificate fails with ErrAlreadyRevoked. PublishCrl sets issuer.crl_number to the CRL's number only on the issuer whose SKID is the CRL's IKID and only when the number is greater (query.SetIssuerCrlNumber, which does not touch updated_at), copies the tenancy and issuer name from that issuer row, and upserts the crl row by IKID in the same transaction; a mismatched IKID is an error, a number that is not greater fails with ErrStaleCrlNumber, and in both cases nothing is stored. UpdateIssuer validates the config as a pb.IssuerConfig document and with Destroyed clears key_protected; ActivateIssuer matches `status = Pending`, so another status is not found. RegisterRoot upserts only within the same org scope: the conditional ON CONFLICT update returns no row for another scope, which is mapped to ErrRootConflict. listRows runs a list with ExecuteQueryWithCursor when the request carries a Cursor, else ExecuteQueryWithPagination; xdb reports a next page when a page is full, so the page after an exact multiple of the limit can be empty. Tests need the configured PostgreSQL database (provider_test.go TestMain); the CA tests build certificates with tests/testutils.NewTestCA and give platform rows random labels (ca_test.go).

Invariant: Request structs own QueryParams and pagination; a query is built through xsql GetOrCreateQuery under a stable name, and its SQL is cached by name. Table definitions come from internal/db/schema. Scope filters (scope.go): the project is `project_id = ?`, `IS NULL` (Scope Org) or `IS NOT NULL` (Scope Project) by setProjectScope; the org of a CA table is `org_id = ?`, `IS NULL` (Platform) or, only with AllOrgs, unfiltered by setOrgScope (each List request's Validate returns ErrOrgScopeRequired otherwise); Find requests use setTenancy, where a zero ID is NULL, and mutations match `org_id IS NOT DISTINCT FROM ?` with OrgArg (whereOrgIs, DeleteRowByOrgAndID). The SQL literals Now(), '' and NULL are the expr* constants of common.go. IS NULL predicates are recorded as null columns of the QueryParams, which the query name hashes, and the WHERE clauses of a builder follow the order of the Set calls of its request, because the positional arguments do. CA lists order by id DESC and page with setPage/pageByID (cursor.go): an offset page adds LIMIT and OFFSET, a cursor page `id < ?` and LIMIT with the last ID of the previous page, which EncodeCursor encodes as a string id. setPage is the last call of a QueryParams, because xdb refuses positional arguments after the limit. GetRowByColumn caches per table and column.

## Build, test and CI

- Go 1.27 (`go.mod`). `make tools` installs the lint, coverage, docs, PKI,
  schema, migrate and mock tools listed in `Makefile`.
- `mocks/` and `api/version/current.go` are gitignored: run `make generate
version` on a fresh checkout before building or testing.
- `make build` builds `trustyca`, `trustycactl`, `trustycasvc`. `make generate`
  runs `go generate ./...` (gomock); `make proto` generates public and private
  protobuf artifacts in Docker; run `make proto generate` when mocks or
  service interfaces depend on the change.
- Local fixtures: `make folders gen_test_certs start-localstack`, then
  `make drop-sql start-sql` **only for a disposable local database**. The
  compose stack (`docker-compose.trustyca.yml`) supplies PostgreSQL, Redis,
  LocalStack and KMS; tests load `etc/dev/trustyca-config.unittest.yaml`.
  `make test` starts nothing.
- `make test` runs the tests; `make testshort` passes `--test.short`, but
  package setup can still need the local stack. `make test RACE=true` enables
  the race detector.
- `make lint` runs formatting and golangci-lint (`.golangci.yml`, which
  excludes SA1019); `CI=true` skips staticcheck/unused. `make vulns` runs
  govulncheck (install it first).
- `make covtest` writes per-package coverage and `coverage.out`;
  `make coverage` opens the HTML report (`.project/gomod-project.mk`).
- `.github/workflows/build.yml` prepares generators, builds binaries and
  starts fixtures. Pushes run `make test`; PRs run `make covtest` and publish
  a coverage status against `MIN_TESTCOV`, which the workflow does not set
  yet. Lint, race checks and the container integration test are local;
  `make docker-citest` points to a `scripts/integration` folder that does not
  exist.
- `make docs` regenerates `Documentation/api/` and `Documentation/cli/`;
  build the CLI binaries first.
- A `.VERSION` change pushed to main creates a `<.VERSION>.<commit count>`
  tag through `build.yml`.
